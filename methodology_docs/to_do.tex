\section{Plan A: Slates (fill from scratch)}

\textit{Scope:} Docs that are placeholders only: \texttt{ctcc\_documentation.tex}, \texttt{weighted\_miles\_documentation.tex}, \texttt{json\_loaders\_documentation.tex}, \texttt{json\_output\_manager\_documentation.tex}, \texttt{smart\_loaders\_documentation.tex}, \texttt{smart\_output\_documentation.tex}, \texttt{path\_config\_documentation.tex}, \texttt{revenue\_documentation.tex}.

\textit{Goal:} Turn each slate into a complete doc (concept + math/model + relevant code). One doc per iteration; same steps each time. Reference structure: \texttt{congestion\_curtailment\_reduction\_documentation.tex}.

\subsection{Process (per slate)}

\begin{enumerate}
  \item Open the script and its \texttt{.tex} side by side.
  \item \textbf{Introduction:} Replace the placeholder with one or two sentences on what the script does and its role in CTCC.
  \item \textbf{Method overview:} Purpose: replace with a short numbered list of what the script actually does (trace \texttt{main()} and key calls). Calculation approach: if there is real logic/formulas, write equations to match the code; if it is I/O or dispatch only, say so in one sentence. Inputs/Outputs: fill from the script (what it loads, what it writes; env vars if relevant). Integration: list the scripts it imports from and who imports it (or ``used by all calculation scripts when\ldots'').
  \item \textbf{Key functions:} For each important function, add a subsection: name/signature, parameters, return value, and a short ``Key logic'' \texttt{lstlisting} snippet from the current script.
  \item \textbf{Example:} Replace with a minimal example (e.g.\ env vars + one call, or one input/output snippet).
  \item Compile the \texttt{.tex} and skim the PDF; mark that slate done in the tracking list.
\end{enumerate}

Also any doc that covers \texttt{calculation\_utils} or \texttt{constants} (e.g.\ inside \texttt{utilities\_documentation.tex}).

\textit{Goal:} Bring each doc in line with the current script: fix concept drift, refresh math, and refresh code. One doc per iteration; same steps each time.

\subsection{Process (per existing doc)}

\begin{enumerate}
  \item Open the script and its \texttt{.tex} side by side.
  \item \textbf{Concept check:} Introduction: does it still describe what the script does? Update if the script's role or steps have changed. Purpose: do the bullets match the script's current flow (e.g.\ new steps, reordering, removed logic)? Inputs/Outputs: align with current loaders and output usage (env, file paths, keys). Integration: update the ``integrates with'' list to match current imports and callers.
  \item \textbf{Math check:} Calculation approach: do equations, variable names, and edge cases (e.g.\ reconductoring, zero credits) match the code? Update or add equations from the script/comments.
  \item \textbf{Code check:} Key functions: do the listed functions still exist with the same role? Add any new important functions; remove or rewrite subsections for renamed/removed logic. Snippets: replace every \texttt{lstlisting} with the corresponding current code (or a short excerpt). Fix any outdated variable names or logic.
  \item \textbf{Example:} If there is an example, check it still runs or matches current behavior; update or add one if missing.
  \item Compile the \texttt{.tex} and skim the PDF; mark that doc done in the tracking list.
\end{enumerate}
